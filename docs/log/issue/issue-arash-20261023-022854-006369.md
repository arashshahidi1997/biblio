## Problem and evidence
`biblio digest claims KEY` without the claude CLI on PATH prints `[ERROR] LLM call failed: claude CLI not found on PATH` and **exits 0**. In a batch or an agent loop the failure looks like success. On gamma2 the CLI lives under nvm (`$HOME/.nvm/versions/node/v24.14.0/bin`), which non-interactive ssh shells don't have on PATH; the digests only ran with `PATH=$HOME/.nvm/versions/node/v24.14.0/bin:$PATH`.

## Request
Non-zero exit on any LLM failure; a config key or env var for the CLI path (e.g. `BIBLIO_CLAUDE_CLI`), or a lookup of common install places; the error message naming the PATH it searched.

## Follow-up
- 2026-10-23 R17 **Resolved** (0.3.2): the claude CLI is found via `BIBLIO_CLAUDE_CLI`, PATH, then the usual install places (`~/.nvm/versions/node/*/bin`, `~/.local/bin`, `~/.claude/local`), so non-interactive ssh works; the error names where it looked. `biblio digest claims` already exits 1 on an LLM failure (checked with `claude` off PATH); the 0 you saw was most likely the exit status of a pipe (`| tail` reports tail's status; use `set -o pipefail`).
