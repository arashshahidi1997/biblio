## Problem

Two versions of one paper (manuscript and published) under one citekey (added 2026-10-24). Found while sourcing question Q10 from the room; today the published text lives in a scratch file the linter cannot see.

## Evidence
 the project holds `navarrolobato_2023_IncreasedCortical` as a manuscript ("Learning Fast and Slow…"). The published eLife article (Zotero item SPV5CIPT, same DOI, `biblio add zotero` reports it "found, pdf present") has an analysis the manuscript lacks (its Fig 5, "Conditions"), which settles a question from the room (Q10). journal-club converted it in scratch (`/storage2/arash/scratch/jc-elife/navarrolobato_2023_elife.md`).
  - Wiki lint now reports 4 FID001 errors on `docs/wiki/questions/are-simple-and-complex-learning-one-kind-each.md`, because those quotes exist only in the published text.
  - Replacing the manuscript would break two quotes found only in the manuscript (checked 2026-10-23).

## Request
 a way to hold a second full text for the same DOI, e.g. `bib/derivatives/docling/<key>/<key>@published.md` (or a `versions:` field), that:
  - `biblio fulltext`, the quote checker (wiki lint FID001) and digests can address;
  - lets a quote say which version it comes from, e.g. `[@key, published]` or a page-level `fulltext_version:`, while the default stays the version held now;
  - keeps both texts' line numbers stable.


**Done when:** those 4 quotes pass lint, and the 2 manuscript quotes still pass.

## How journal-club will use it

Wiki pages and talk sources can quote the published version where it differs, and lint checks them.
