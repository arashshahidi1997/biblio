Reported 2026-11-08 by pix-maintenance · bibliography (pixecog handoff 20261108-142632-627152), at the user's direction.

1. `biblio bibtex backfill-venue` writes registry HTML entities verbatim: Crossref container-title "Learning &amp; Memory" became `journal = {Learning &amp; Memory}`. _bibtex_escape only escapes \ { }. Expected: html.unescape, then escape & as \&. 5 of 495 pixecog entries fixed by hand.
2. `biblio graph promote --seed swanson_2025_TopographyPutative --dry-run` fails with "seed citekeys not found in resolved.jsonl" although the key is there. Two citekeys (Swanson_2025_Topography, swanson_2025_TopographyPutative) share OpenAlex id W4406867193 and graph._seed_citekeys maps id->key, so one key is lost. The other key works, but its summary prints "by seed: -" when 0 are added.
3. `biblio bibtex fetch-pdfs-oa --citekeys <254 keys>` prints only 5 of 238 errors ("... and 143 more errors"; the count does not add up) and its progress shows "[250/250] None". Expected: the full failure list (or a TSV path) and no None entry. The no_pdf_html_saved classification worked.
4. (packaging, projio side) projio[all] pulls PyPI biblio-tools 0.1.5 even when projio is installed editable, so pixecog silently lacked backfill-venue and graph promote; pixecog added its own editable override (pixecog 18d67db4). Uploading biblio-tools 0.3.6+ to PyPI closes the gap for PyPI installs; consider a version floor or a warning when versions diverge.
