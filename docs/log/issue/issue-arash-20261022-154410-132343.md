## Problem

The user's master library is Zotero on the laptop. Bringing one paper into a project takes several manual steps across two machines, and the citekey has to be renamed by hand.

## Evidence

- Today's path for the target paper: find it in Zotero (laptop) → copy the PDF to `bib/articles/<key>/<key>.pdf` → export BibTeX from the Zotero local API and rename the key → `datalad save` + `push` to gamma2 → `biblio grobid run` and `biblio docling run` on gamma2.
- Citekeys differ: Better BibTeX gives `aleman-zapata_2026_DeltasSpindles`, the pools use `alemanzapata_2026_DeltasSpindles`.
- Zotero on the laptop: Zotero 9, Better BibTeX, local API at `localhost:23119`, a zotero-mcp server. gamma2 can reach only the Zotero web API.
- `zotero.py` `pull` (web API by default, `local: true` for the local API) syncs a library or collection, not one item.
