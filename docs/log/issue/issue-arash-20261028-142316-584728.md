# [from lit-studio, R47] docling JSON embeds every page as a base64 image (about 20 MB per paper) although image_export_mode is referenced

## From

**lit-studio**, formerly journal-club (laptop `~/dev/projects/lit-studio`, the main copy; gamma2 `/storage2/arash/projects/lit-studio`). It is the user's personal knowledge base for the field (wiki, digests, figure crops; analysis methods as a second subject) and the talks made from it; the same client that filed R01–R41 with you. Intro: `/storage2/arash/projects/lit-studio/docs/for-other-projects.md`. Current run: `backlogs/2026-10-23-alemanzapata-tooling.md`. Filed with the user's authorization on 2026-10-28.

## Problem

`biblio docling` writes `<key>.json` with a full rendering of every page embedded as a base64 data URI under `pages[*].image`. The figure crops are written as files in `<key>_artifacts/` (pictures are referenced, as configured), so the page images are the only thing embedded, and they make the JSON 100 to 200 times the size of the full text. Nothing in biblio reads them.

## Evidence

- lit-studio's `.projio/biblio/biblio.yml` sets `docling.image_export_mode: "referenced"`; `docling.py` lines 168–177 pass it as `--image-export-mode`.
- `schreiner_2022_HumanThalamus.json` (gamma2, `lit-studio/bib/derivatives/docling/`): 20 MB. Of that, `pages` is 19.8 MB (16 pages, all 16 with a `data:` image URI); `texts` 428 KB; `pictures` 18 KB (10 pictures, none embedded). The `.md` is 92 KB and the `_artifacts/` folder 1.7 MB. `lemieux_2014_ImpactCortical.json` 19 MB and `zucca_2017_InhibitoryGate.json` 28 MB, same pattern.
- All of lit-studio's 71 docling folders: 1.3 GB of JSON.
- Readers of the JSON use only page sizes, not page images: `figures.py` lines 401–411 (`pages[*].size`), `ui.py` line 1956 and `present.py` line 77 (`pictures[*].image.uri`). lit-studio's own `code/figures.py` crops from the PDF.
- Cost: on 2026-10-28 lit-studio found its git pack at 607 MiB, mostly from 53 of these JSON files in plain git (1.02 GB at HEAD), because its annex rule only caught binaries. It now annexes them (`.gitattributes`, commit 2d39a73c), but the history can't be published without a rewrite, and every clone or backup carries the page images. The same will hold for any project that commits docling output, and for the pools.

## Request

1. Write the JSON without page images by default when the mode is `referenced` (keep `pages[*].size` and the rest). Either a docling option, if one does it, or a post-processing step in `docling.py` that drops `pages[*].image` before the file is written. A config key (e.g. `docling.page_images: false|embedded`) if some project needs them.
2. A command to slim JSON already converted, in place, without re-running docling (e.g. `biblio docling slim [--key K | --all] [--dry-run]`), reporting the bytes saved. lit-studio would run it on its 71 folders; the pools too, if their owners want.
3. Say in the docs which parts of the JSON biblio relies on, so projects know what is safe to drop.

## How lit-studio will use it

New conversions stay small; the slimmed JSON goes back into the annex in place of the 20 MB files, so backups and clones shrink. lit-studio's figure crops and wiki embeds use the PDF and `_artifacts/`, so nothing on our side depends on the page images.

## Follow-up
- 2026-10-28: done in 2d1d4ff (biblio 0.3.5, backlog I11). Verified first: biblio reads `pages` (keys and `size`), `texts[*]` (`text`, `prov`, `self_ref`) and `pictures[*]` (`prov`, `captions`, `image.uri`); nothing reads `pages[*].image`. (1) Page images are dropped after each conversion (a post-processing step; docling has no option for it), unless `docling.page_images: true` (default: kept only with `image_export_mode: embedded`). (2) `biblio docling slim --key K | --all | --dir DIR [--dry-run]` slims existing JSON in place: temp file in the same folder, renamed over the old one, so a locked annex symlink becomes a regular file and the annex object is untouched; an annexed file without content is skipped with a `datalad get` hint; reports bytes per file and in total, exit 1 if anything was skipped. `--dir` takes any docling root, e.g. a pool's `derivatives/docling`. On copies of `schreiner_2022_HumanThalamus` and `timofeev_2001_DisfacilitationActive` in /tmp: 20.0 MB -> 669 KB and 7.2 MB -> 207 KB, JSON otherwise identical to the original. (3) `docs/how-to/docling.md` "What biblio reads from the JSON". 14 tests (`tests/test_docling_slim.py`). Not run on lit-studio's files or the pools: run `biblio docling slim --all --dry-run` then `--all`, then `datalad save`.
