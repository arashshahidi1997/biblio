## Problem

Extract named papers, including new ones, without touching anyone else's. Today's work (sourcing the room's 16 questions, adding 14 papers from Zotero) did this step one paper at a time or with a scratch script.

## Evidence

  - `biblio docling batch --concurrency 2` reported `pending=1 already_done=21`: it saw only the 22 keys in `merged.bib`, skipped all 14 new papers silently, and converted `steriade_nd_IntracellularAnalysis` instead, a pending paper from **another session** working in the same gamma2 copy (journal-club runs several sessions there at once);
  - `biblio grobid run --key` found the same 14 new keys, so the two tools disagree about which papers exist;
  - `biblio merge` no longer exists (`biblio bibtex merge`), but projio's tool table in journal-club's CLAUDE.md still says `biblio_merge()` (a note for projio, not biblio);
  - fallback was 14 serial `biblio docling run --key` calls, one docling run took 4 min 36 s (the batch log).

## Request

  - `biblio docling batch` and `biblio grobid run` take explicit keys (`--keys a,b` or `--from list.txt`);
  - a paper added with `biblio add` is visible to these tools at once (the batch reads srcbib too, or `add` refreshes the merged bibliography);
  - the batch says which keys it skipped and why ("not in merged.bib", "no PDF", "done");
  - optional: from the laptop, `biblio add … --extract-on gamma2` (or a queue gamma2 drains), so the laptop needs neither docling nor GROBID.


**Done when:** `biblio docling batch --keys <the 14>` converts exactly those 14 and nothing else.
