# [from lit-studio, R55] Make biblio shareable as a minimal, independent tool: install, README, CLI scope, CI, release, optional own MCP server

## From

lit-studio (formerly journal-club): the user's knowledge base for the field and the talks made from it. It uses biblio's on-disk outputs as its interface. See `lit-studio/docs/for-other-projects.md`. No active run backlog for this one; it's tracked in `docs/plans/lab-knowledge-base-kit.md`.

## Problem

The supervisor asked for "a skill and pipeline to run/use docling". The plan is to share a minimal agentic paper toolkit with the lab, and later with outsiders in the agentic workshop: Zotero → docling → GROBID → reading with exact quotes. biblio is the natural tool for it. A review of biblio on 2026-11-03 found the pipeline commands ready, but the package not ready for someone new.

## Evidence

Review of the laptop copy at 0.3.4 (`~/dev/projects/projio-eco/packages/biblio`):

- **Install:**
  - There's no docling extra; docling runs as an external command (`docling.cmd`). The pinned pixi env `docling` exists only in gamma2's `pixi.toml` (R48).
  - There's no GROBID setup in the install docs.
  - `pyproject.toml` says Python `>=3.9` (classifiers 3.9–3.11); `pixi.toml` pins `>=3.11,<3.13`.
- **README:** it describes biblio as "Docling scaffolding + RAG + site", lists Python 3.9, and has no walkthrough of Zotero → docling → GROBID → figures from an empty folder.
- **CLI:** `biblio --help` lists 36 subcommands. About half are experimental or slated to move in `docs/explanation/scope.md`, which is still a proposed draft: present, summarize, concepts, compare, reading-list, cite-draft, review, ui, graph, auth and others.
- **Known bugs** listed in scope.md:
  - OpenAlex returns the wrong work for some arXiv DOIs;
  - book authors are dropped;
  - every entry is typed `@article`;
  - citekeys are mangled for multi-word family names and for letters like `ø`.
- **Tests:** 484 pass (`pixi run -e dev test`, 9 s), but all are mocked; nothing runs docling or GROBID end to end. `.github/workflows/` has only `docs.yml`, so CI doesn't run the tests.
- **Release:** the CHANGELOG has a large Unreleased section, and nothing local shows the package on PyPI.
- **Skills:**
  - Of the skills biblio ships, `zotero-add` works without projio. `literature-sourcing` and `biblio-batch-curate` need projio's MCP tools (`paper_lookup`, `biblio_job`).
  - projio still ships an older copy of `biblio-batch-curate` that calls `biblio_merge()` and `biblio_compile()`. The CHANGELOG says this skill moved to biblio.
  - biblio has no MCP server of its own; `src/biblio/mcp.py` holds the functions behind projio's tools.
- **Lab specifics in code:** they're opt-in and harmless (`profiles/sirota.yml`, the "sirocampus" name in `refs.py:168`, `gamma2` in the CLI help examples around `cli.py:638,661`).

## Request

A minimal, independent biblio. Each item can be done on its own:

1. **Install:** a `docling` extra or documented install with the pinned versions (2.64.1 and companions, CPU torch), and a GROBID one-liner (docker). Make the Python range agree.
2. **README:** rewrite it around the pipeline, with a quickstart from an empty folder: `init` → `add zotero` / `add doi` → `docling run` → `grobid run` → `figures run` → `quotes check`.
3. **Scope:** mark the experimental commands as such in `--help` and the README, or move them behind an extra, following scope.md.
4. **Known bugs:** a short known-issues note for the metadata and citekey bugs until they're fixed.
5. **CI:** run the tests, plus one end-to-end test on a small open-access PDF if docling is available.
6. **Release:** release the Unreleased changes (0.3.5 or 0.4.0) and confirm the PyPI upload.
7. **Skills:** remove projio's stale `biblio-batch-curate`, and mark which shipped skills need projio.
8. **Optional MCP server of its own:** `biblio mcp`, behind an `mcp` extra, as an alternative to projio's. It serves the functions already in `mcp.py`, so projio and biblio share one implementation.
   - **Minimal tool set:** paper lookup (key → paths, metadata), full text and section read, quote check, add from Zotero or DOI, docling/GROBID run and job status, pool lookup.
   - **Why:** skills that now need projio (e.g. `literature-sourcing`) would work with biblio alone, and a Claude Code plugin can start the server from its own `.mcp.json`.
   - **Open:** scope.md lists "which MCP tools stay" as undecided. This request suggests the minimal set above as the answer for the standalone server.

## How lit-studio will use it

- **The lab plugin** (`lab-papers`, phase 0 of the plan) uses biblio's CLI. When `biblio mcp` exists, it starts it from its own `.mcp.json` and drops its own scripts where biblio covers them; the quote check is the first.
- **The public workshop version** installs biblio from PyPI with the docling extra.
- **lit-studio's `code/ingest.py`** (Zotero → biblio → gamma2 → pull) is the concrete case for a later "ingest" command. That would be a separate request once the plugin pilot has run.
