# [from journal-club, R04] Figures at native resolution: embedded images first, else re-render docling's bbox at 300 dpi

## From

**journal-club** (`/storage2/arash/projects/journal-club`; laptop clone `~/dev/projects/journal-club`), filed by its agent session on 2026-10-22 with the user's authorization.

journal-club turns one paper plus the literature it builds on into talks (background, intro, full, single slide) for the Sirota lab's Friday lab meeting. It reads papers through biblio's on-disk outputs (docling, GROBID, pools, `merged.bib`), is building a knowledge wiki with biblio's wiki toolkit, gets visuals from viz-studio, and synthesizes a Quarto deck from the wiki. Each talk is used as a forcing goal for the tooling, so gaps come to you as requests like this one. Intro for other projects: `/storage2/arash/projects/journal-club/docs/for-other-projects.md`.

**Current run:** the 2026-10-23 lab meeting on `alemanzapata_2026_DeltasSpindles` (Aleman-Zapata et al., *SLEEP* 2026, "Deltas' and spindles' cross-area synchronization and ripple subtypes"). Tracking: journal-club `backlogs/2026-10-23-alemanzapata-tooling.md` → section "Requests filed".

## Problem

docling's figure crops are page renders at 144 dpi, about half the resolution the PDF already holds. Too soft for slides, and the wrong input for viz-studio.

## Evidence

- `docling.py:168-178` passes only `--to` and `--image-export-mode`; there is no scale or dpi setting.
- For `alemanzapata_2026_DeltasSpindles`: docling crops ~900 px wide (e.g. Fig 1: 690 × 981); `pdfimages -list` shows each figure embedded as a 300 ppi JPEG ~1900 px wide (Fig 1: 1446 × 2033).
- docling's JSON already has each picture's `page_no` and `bbox` (BOTTOMLEFT origin).

## Request

- A figure step after docling. For each picture: take the embedded image that covers the bbox (`pdfimages -j` or PyMuPDF, lossless), else re-render the bbox with `pdftoppm` at a configurable dpi (default 300).
- Write `bib/derivatives/figures/<key>/fig-<n>.<ext>` plus a manifest: figure number, caption (from the docling JSON), page, bbox, source (embedded or rendered), pixel size.
- Panel splitting can come later.

## How journal-club will use it

Figures embedded in wiki source pages, the talk deck, and viz-studio requests (redraws and animations of the paper's panels).

journal-club `backlogs/2026-10-23-alemanzapata-tooling.md`: request R04, backlog item T06.

- 2026-10-22 (journal-club, after trying `biblio figures run`): thanks, it works and finds the embedded images. Tried on alemanzapata_2026_DeltasSpindles and maingret_2016_HippocampoCortical in journal-club; compared with journal-club's prototype `code/figures.py` (PyMuPDF), which builds the figure store for its viz-studio hand-off (`docs/figure-handoff.md`). Gaps, most important first:
  1. **Figure numbers and captions.** Maingret 2016: all four figures come out `number: null` with wrong captions (a statistics line, sentence fragments), because docling linked the real captions to ~80 px margin icons. Fix that worked in the prototype: skip pictures under ~1% of the page before reading captions; when a picture's linked caption doesn't start with "Fig./Figure N", take the nearest unused "Figure N" text on the same page (by vertical distance).
  2. **Extended Data and Supplementary figures** need names (`ed4`, `figS2`); docling splits some ED pages into several pictures (sebastian_2023: 24 pictures for 7 main + 10 ED figures).
  3. **Graphical abstract**: the target's GA is `pic-05`, unnamed. The prototype names it `ga` when the page has a "Graphical Abstract" text.
  4. **Logos and cover sheets**: `pic-00`/`pic-01` are the Radboud repository cover logos. A size threshold relative to the page (5% for uncaptioned pictures) drops them.
  5. **Vector art**: for vector or mixed figures, a one-page PDF cropped to the figure box (PyMuPDF `insert_pdf` + `set_cropbox`) lets viz-studio animate the original vector art (`paper-figure-steps`). The PNG render alone loses that.
  6. **Manifest fields for provenance**: `pdf` is the resolved annex object path (`.git/annex/objects/...`); a project-relative path is stabler. Missing for the hand-off: `pdf_sha256`, `pdf_version` (publisher | accepted | submitted | preprint), `credit` line, `licence`, per-file `sha256`, and a figure `ref` (`<citekey>:fig1`). `art` (raster | vector | mixed) is useful to the studio.
  7. **Pool papers**: `--key` worked for maingret, whose docling output is only in a pool (good).
  journal-club keeps its own `figures/<citekey>/` store for now and will switch to `bib/derivatives/figures/` once 1-6 are covered; the prototype's field names are in journal-club `figures/<citekey>/manifest.yml`.
