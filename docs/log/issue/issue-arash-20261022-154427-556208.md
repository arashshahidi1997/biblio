## Problem

A talk's background starts from the target paper's reference list: which references can we read now, which need a PDF, which are absent? biblio's existing check covers only the project's own bib, with exact matching.

## Evidence

- `grobid.get_absent_refs` (`grobid.py:505-560`, behind the `paper_absent_refs` MCP tool) reads the project's srcbib only (`grobid.py:481`), ignores `pool.search`, and matches an exact DOI or an exact normalized title. No year, no fuzzy matching, no OpenAlex.
- journal-club's prototype on the 66 GROBID references of `alemanzapata_2026_DeltasSpindles`: DOI against both pools' `merged.bib` (noting whether docling output exists) and the laptop Zotero DB (read-only sqlite, noting whether a PDF is attached), then a fuzzy normalized-title match. Result: 19 converted in a pool, 19 PDFs in Zotero, 2 metadata only, 26 absent (about half methods references). Output: journal-club `papers/alemanzapata_2026_DeltasSpindles/refs.json`.
- This paper's references had DOIs (65/66) because the PDF prints them. In the pools about 79% of GROBID references lack a DOI, because `consolidate_citations` defaults to false (`config.py:157`).

## Request

- A command (name open, e.g. `biblio refs triage <citekey>`) that gives each reference a status: in a pool with docling / PDF available / metadata only / absent. JSON and markdown output.
- Search the project bib and the pools, optionally a Zotero export, and fall back to OpenAlex `referenced_works` for the target.
- Consider `consolidate_citations: true` as the default.

## How journal-club will use it

journal-club picks the background papers from the triage, and lists the absent ones for one-by-one Zotero capture.
