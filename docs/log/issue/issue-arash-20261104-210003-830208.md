## From

lit-studio (formerly journal-club), the lab's field knowledge base built on biblio's wiki tooling. How to work with it:
`docs/for-other-projects.md` in lit-studio. Found by the laminar wiki session (2026-11-04,
`sessions/2026-11-04_laminar-wiki.md`); filed by lit-studio's manager.

## Problem

`biblio wiki lint` reports `SYN001` ("**Synthesis:** paragraph without 'Rests on: …'") on the **type heading that biblio
itself generates** in hub page listings. Once a hub lists a synthesis page, its generated block contains a
`**synthesis**` group heading, and `SYNTHESIS_RE` (`src/biblio/wiki/lint.py:216`,
`^\s*(?:>\s*)?\*\*Synthesis:?\*\*:?` with `re.I`) matches it: the colon is optional and the match ignores case. So every
hub that lists a synthesis gets a warning nobody can fix.

## Evidence

biblio 0.3.4 (laptop), `biblio wiki lint --root . docs/wiki/hubs` in lit-studio, 2026-11-04:

```
hubs/hub-laminar-recording.md   73  warning  SYN001  **Synthesis:** paragraph without 'Rests on: ...'  [P8]
hubs/hub-sleep-coupling.md     238  warning  SYN001  ...
hubs/hub-spindles-thalamus.md  163  warning  SYN001  ...
hubs/hub-swr-fundamentals.md   (same)
```

`docs/wiki/hubs/hub-laminar-recording.md` lines 72–76, inside the generated block:

```
**synthesis**

- [Layer markers by structure](../syntheses/layer-markers-by-structure.md) (draft)
<!-- biblio:pages:end -->
```

## Request

Don't flag the generated listing. Either (a) skip lines inside `<!-- biblio:pages:start -->` … `<!-- biblio:pages:end -->`
in all prose rules, or (b) require the colon and the capital S (`**Synthesis:**`), the form W23 defines. (a) also protects
the other rules from generated text. A regression test with a hub that lists a synthesis.

## How lit-studio will use it

`check_page.py` and lint run on every touched page before a save; a warning that can't be fixed trains sessions to
ignore SYN001, including the real ones on synthesis paragraphs.
