**Current run:** biblio 0.2.0 trial (Arash's request, 2026-10-22) on `alemanzapata_2026_DeltasSpindles`: `refs triage`, `wiki init`, the `wiki-ingest` skill, `figures run`, `wiki figure`, `wiki review packet`. ## Problem

journal-club had no `.projio/biblio/merged.bib` (entries live in `bib/srcbib/journal-club.bib`). `biblio wiki lint` reported every citation of the project's own target paper as missing. `biblio refs triage` in the same repo found project papers fine (`project:navarrolobato_2023_...`). The message claims the key is "not in the bibliography or any pool", which is wrong and sends an agent looking in the wrong place.

## Evidence

```
biblio wiki lint
concepts/ripple-subtypes.md
    32  error      CIT001   @alemanzapata_2026_DeltasSpindles is not in the bibliography or any pool  [P8]
... 9 errors, one per page
```

`wiki/schema.py:100-101`: bibliography = compiled.bib, else merged.bib, else bib/main.bib; no srcbib fallback. After `biblio bibtex merge`: 0 errors.

Expected: the same project-bibliography resolution as the rest of biblio (`load_active_citekeys`, merged bib with fallback to a srcbib scan, per the 0.2.0 changelog), or an explicit "no project bibliography found (run biblio bibtex merge)" error once, instead of one CIT001 per citation.

## Request

Use `load_active_citekeys(cfg)` (or the same fallback) in lint and the review packet; when no bibliography file exists, say so once.

## How journal-club will use it

Lint on every ingest; journal-club adds papers one at a time and doesn't always re-merge.

journal-club run backlog, request R12 (T12).
