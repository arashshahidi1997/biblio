## Problem and evidence

1. **`ui serve` install hint doesn't fit a uv tool install.** On the laptop biblio is a uv tool
   (`uv tool install -e ".../biblio[zotero,openalex]"`); `biblio ui serve` fails and says `pip install "biblio-tools[ui]"`.
   The hint should name the uv form (`uv tool install --reinstall -e "<path>[...,ui]"`) or the extra only.
2. **`site build --out-dir` refuses paths outside the repo.** lit-studio renders locally only (its decision D40: journal
   figures stay internal), and wanted the site in a scratch folder outside the dataset. An explicit `--out-dir` should be
   allowed anywhere, perhaps with a warning.
3. **`wiki lint` reads only the laptop copy of a paper's full text.** A supplement held under the main key on gamma2 gave
   false FID001 (quote not found) on the laptop (lit-pix-ontology, 2026-11-05).
4. **Silent failures:** `biblio locate --openalex` and `biblio add zotero --local` each failed without an error message
   once in lit-pix-ontology's session (2026-11-05); exit status 0, nothing done. A non-zero exit and a reason would do.
5. **Pool gap:** `kim_2019_` (Kim et al. 2019, rat M1 slow oscillations vs delta) has docling but no GROBID output in
   pixecog's pool (`/storage2/arash/projects/pixecog/bib/derivatives/`).

## Resolution (2026-11-11)

With the 0.4.0 release (R55):

1. **ui hint:** every missing-extra message (`ui serve`, `pool serve`, Zotero, `biblio mcp`) names the uv tool form, `uv tool install --reinstall "biblio-tools[<your extras>,ui]"` (or `-e` with a path), and pip (`biblio._extras.install_hint`).
2. **`site build|clean --out-dir` outside the repository:** allowed when the folder is new, empty or an earlier biblio site (`_data/`, `style.css`), with a warning; the home folder, `/` and the repository's parents are refused, since rebuilds replace the folder. Test `test_site_out_dir_outside_the_repo`.
3. **`wiki lint` on the laptop:** not changed. Lint reads the texts this machine has (project, then the pools it can see); on a laptop the gamma2 pools are not there. Copy the supplement's text into the laptop's project (`bib/derivatives/docling/<key>/`) or lint on gamma2.
4. **Silent failures:** `biblio locate --openalex` swallowed every OpenAlex error (offline, rate limit, a missing `openalex` extra) and showed the item as "not held" with exit 0; live Zotero lookups did the same. A failed lookup is now shown on the item's row ("lookup failed: ...") and the command exits 1. `add zotero` already exits 1 for refs not found; `--extract` failures now do too. If `add zotero --local` recurs silently, the command and its output would help.
5. **Pool gap `kim_2019_`:** pixecog's pool, so pixecog's to run (`biblio grobid run --key <key>` there).
