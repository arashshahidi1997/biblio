## From

lit-studio (formerly journal-club), the lab's field knowledge base built on biblio; `docs/for-other-projects.md`.

## Problem and evidence

1. **`ui serve` install hint doesn't fit a uv tool install.** On the laptop biblio is a uv tool
   (`uv tool install -e ".../biblio[zotero,openalex]"`); `biblio ui serve` fails and says `pip install "biblio-tools[ui]"`.
   The hint should name the uv form (`uv tool install --reinstall -e "<path>[...,ui]"`) or the extra only.
2. **`site build --out-dir` refuses paths outside the repo.** lit-studio renders locally only (its decision D40: journal
   figures stay internal), and wanted the site in a scratch folder outside the dataset. An explicit `--out-dir` should be
   allowed anywhere, perhaps with a warning.
3. **`wiki lint` reads only the laptop copy of a paper's full text.** A supplement held under the main key on gamma2 gave
   false FID001 (quote not found) on the laptop (lit-pix-ontology, 2026-11-05).
4. **Silent failures:** `biblio locate --openalex` and `biblio add zotero --local` each failed without an error message
   once in lit-pix-ontology's session (2026-11-05); exit status 0, nothing done. A non-zero exit and a reason would do.
5. **Pool gap:** `kim_2019_` (Kim et al. 2019, rat M1 slow oscillations vs delta) has docling but no GROBID output in
   pixecog's pool (`/storage2/arash/projects/pixecog/bib/derivatives/`).

## Request

Whatever fits biblio's plans; none blocks lit-studio. Items 1, 2 and 4 are the ones sessions hit.

Items 1–2 for the local reading render (J33); 3–4 for page checks and captures.
