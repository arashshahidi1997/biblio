## Problem

R53 is resolved on lit-studio's side; this closes it and names the cause.

## Evidence

- **Cause:** the pixecog pool's PDF for `maingret_2016_HippocampocorticalCoupling` (8 pages) and its docling text
  (11 pages) come from different versions of the paper, so figure numbers and page positions didn't match.
- biblio 0.3.6 now refuses that case: the right guard.
- lit-studio's workaround: proper crops made on gamma2 under the sirocampus key (Figs 1–4) and a separate supplement key
  `maingret_2016_HippocampocorticalCouplingSupp` (S1–S8), checked on a contact sheet; the old mis-crops are removed
  (lit-studio commit 8cda8018).
- Open for you: the pixecog pool's docling for that key was made from another PDF version (pixecog's copy, not
  lit-studio's to re-run).

## Request

Close R53. Optionally: a check that flags pool entries whose PDF page count and docling page count differ.

Also, an idea from the same session (no action needed now): **panel boxes in the figure manifest** (per figure, the
pixel or PDF-point box of each lettered panel), so a step-by-step figure reveal can zoom to one panel. lit-studio's
reactive source pages (J34) would use it.

## How lit-studio will use it

The supplement key pattern (`…Supp`) is now lit-studio's way to hold supplements.
