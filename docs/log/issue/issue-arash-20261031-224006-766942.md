# [from lit-studio, R50] wiki lint: make the severity of TAG001 (unknown tag) configurable

## From

lit-studio, the personal field knowledge base and talk workspace (formerly journal-club), `~/dev/projects/lit-studio` (laptop main copy; gamma2 `/storage2/arash/projects/lit-studio`). How it works with other projects: `docs/for-other-projects.md`. Current run: graph-logos / knowledge-base principles (`backlogs/2026-10-30-graph-logos.md`).

## Problem

`biblio wiki lint` reports every tag not in the vocabulary as an **error** (`TAG001`, `src/biblio/wiki/lint.py`, around line 349: `Finding("error", "TAG001", ...)`). lit-studio decided (D32, 2026-10-31) that its vocabulary is **linted, not enforced**: unknown tags are candidates to be reviewed when they recur, never a blocking error. The user: "the strictness of vocabulary might be difficult to maintain, so would not have hard rejection as a machinery, but rather linting as processing".

## Evidence

- lit-studio `docs/decisions/D32-vocabulary-linted-not-enforced.md`; `docs/wiki/SCHEMA.md` §3.
- The SPEC (§3.2) says "lint rejects unknown tags"; lit-studio refines this for itself (D31).

## Request

1. A way to set the severity of `TAG001` per wiki, e.g. a `wiki.yml` key (`tag_unknown: warning`, or a general `severity_overrides: {TAG001: warning}`).
2. Optionally, a candidate report: unknown tags with their page counts, so recurring candidates are easy to process (add to `vocab.yml`, alias, or replace).

## How lit-studio will use it

`wiki.yml` sets `TAG001` to warning; candidate tags are listed and processed when pages are reviewed on use (SCHEMA.md P16).

## Tracking

lit-studio BACKLOG J25; request R50 in `backlogs/2026-10-23-alemanzapata-tooling.md` (requests table).

## Resolution (2026-11-10)

biblio 251e303 (with R65). `wiki.yml` takes `severity_overrides: {TAG001: warning}`: any lint code to `error`, `warning`, `suggestion`, `info` or `off` (a bare YAML `off` is accepted); an unknown level is an error when the config loads. The candidate report is `biblio wiki lint --tag-candidates [--format json|tsv]`: tags outside the vocabulary, most used first, with their pages. SPEC §3 and §11 updated, and `biblio wiki init` writes the key commented. Test `test_severity_overrides_and_tag_candidates`.
