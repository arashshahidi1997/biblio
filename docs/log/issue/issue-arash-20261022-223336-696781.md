# [from journal-club, R09] wiki init --tag fails on first run when the project has .projio/biblio/tag_vocab.yml

journal-club turns one paper plus the literature it builds on into talks for the Sirota lab's Friday lab meeting, and builds a knowledge wiki with biblio's toolkit. Intro for other projects: `/storage2/arash/projects/journal-club/docs/for-other-projects.md`.

**Current run:** biblio 0.2.0 trial (Arash's request, 2026-10-22) on `alemanzapata_2026_DeltasSpindles`: `refs triage`, `wiki init`, the `wiki-ingest` skill, `figures run`, `wiki figure`, `wiki review packet`. Wiki: journal-club `docs/wiki/` (commit a52c0ff). Tracking: journal-club `backlogs/2026-10-23-alemanzapata-tooling.md`, section "Requests filed".

## Problem

On a fresh wiki, `biblio wiki init --subject S --tag event/x` refuses every tag. The config is loaded before `init` writes `docs/wiki/vocab.yml`, so `load_wiki_config` falls back to `.projio/biblio/tag_vocab.yml` (the bibliography's tag vocabulary: corpus, domain, method, task), and `ensure_tags` rejects the facet. The skeleton is written and `init` is logged anyway, then the command exits 1.

## Evidence

Command (journal-club, no `docs/wiki/` yet):

```
biblio wiki init --subject sleep-coupling --tag event/sharp-wave-ripple --tag event/spindle --tag event/delta-wave --tag state/nrem-sleep
error: unknown facet 'event' in tag 'event/sharp-wave-ripple'; known: ['corpus', 'domain', 'method', 'task']. Add it to tag_vocab.yml first.
```

The `vocab.yml` it had just written has the `event` facet. Running the same command again works. Code: `wiki/schema.py:103-105` (fallback), `wiki/scaffold.py:116-140` (`ensure_tags` uses `cfg.vocab`).

Expected: the first run creates the hub and adds the tags to `docs/wiki/vocab.yml`, as the 0.2.0 changelog says ("`--tag` values join `vocab.yml`").

## Request

- Reload the config (or point `cfg.vocab` at the new `vocab.yml`) after writing the skeleton, before `ensure_tags`.
- Consider dropping the fallback to `.projio/biblio/tag_vocab.yml` for wikis: it has a different format (`namespace:value`) and purpose.
- A test: `init --tag` in a repo that has `.projio/biblio/tag_vocab.yml`.

## How journal-club will use it

`init` once per subject; the second subject (T13/T14 backgrounds) will hit this path again only if the vocab file goes missing, but every new project with biblio hits it on day one.

## Tracking

journal-club run backlog, request R09 (T11).
- 2026-10-22 **Resolved** (biblio, after 0.2.0): `wiki init` switches to the wiki's own `vocab.yml` unless `wiki.yml` sets `vocab:` explicitly, so `.projio/biblio/tag_vocab.yml` no longer shadows it; test with a `tag_vocab.yml` present. The fallback stays for wikis without a `vocab.yml` (W14 decides the one-vocabulary question).
